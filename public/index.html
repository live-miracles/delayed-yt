Delayed YouTube keeps a YouTube player at the position you expect. Use live mode for a delayed live stream, or video mode to play a normal video as if it started at a local clock time.

What problem does it solve?

YouTube playback can jump after buffering, network fluctuations, browser refreshes, or player hiccups. In live mode, that can skip the delay you were trying to preserve. In video mode, it can move away from the position that matches the video start time. Delayed YouTube monitors the player and seeks back to the expected position.

Common Uses

  • Keeping an OBS or vMix browser source safely behind LIVE.
  • Watching a live stream with others while preserving a shared delay.
  • Monitoring a broadcast with time to react before the live moment.
  • Playing a normal video as if it started at a local time like 21:30.

Versions

  • Latest version - current master build.
  • Stable version - build from the stable branch.

Known Issues

  1. Due to YouTube Player API limitations, the script only works for live streams that started at least 30min ago. For newly started streams, the script will not correct the skipping.
  2. If the RTMP stream stops for any reason, YouTube will cut out that part. You will then need to manually refresh the script to correct the delay. For example, if you were watching a stream with a 15 min delay and stopped streaming for 5 min, the delay would actually be 10 min.
  3. YouTube may ask you to sign in to confirm that you are not a bot.
    • If you are using vMix, click the YouTube logo in the bottom right corner to sign in to your Gmail account. After signing in, right-click on the input and select "Properties." Then, update the URL.
    • If you are using OBS, create one more browser input with the URL "youtube.com," sign in there, and refresh the script webpage. Afterwards, you can delete the second input.
